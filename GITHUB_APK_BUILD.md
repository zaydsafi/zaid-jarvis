# Build Zaid Jarvis APK with GitHub Actions

This repository includes `.github/workflows/android-apk.yml`. GitHub's hosted runner installs Java 17 and Android SDK 36, runs the Gradle build, and publishes the debug APK as a downloadable workflow artifact.

## One-time setup

1. Sign in to GitHub and create a new repository (for example, `zaid-jarvis`).
2. Upload the **contents** of this project folder to the repository. The `.github/workflows/android-apk.yml` file must be included at the repository root.
3. Commit the files to the `main` branch.

## Build and download

1. Open the repository on GitHub.
2. Select **Actions**.
3. Open **Build Zaid Jarvis APK**.
4. Select **Run workflow** if it has not already started from your push, then confirm **Run workflow**.
5. Open the completed run.
6. Under **Artifacts**, download `zaid-jarvis-debug-apk`.
7. Extract the downloaded artifact ZIP. It contains the APK, normally named `app-debug.apk`.
8. Transfer the APK to your Android phone and install it. You may need to allow installation from that file manager/browser.

## Important notes

- This workflow builds a **debug APK**, not a Play Store release.
- The app's Gradle configuration sets `minSdk = 26` (Android 8.0 or later).
- The debug build uses the debug signing key generated by Android Gradle Plugin.
- GitHub Actions artifacts are retained for 14 days by this workflow.
- The first build may take several minutes while Gradle downloads dependencies.
- If the build fails, open the failed workflow run and inspect the **Build debug APK** log. The failure details will identify whether a dependency, SDK, or source-code correction is needed.

## Triggering a build later

Push a new commit to `main`/`master`, or manually run the workflow from the repository's **Actions** tab.
